# SM-03 billing oracle

Independent check of bill calculation and bill splits. The reference model is written from `docs/PRD.md` v0.5 (commit `dabc649`) and the `computeBill`, `splitEqual` and `splitByItem` signatures in `docs/ARCHITECTURE.md` v1.3 §3 (commit `18560a0`). It does not read the implementation to decide expected amounts.

Money is integer sen (`BigInt`). Rates are basis points (`6% = 600`, `10% = 1000`, `10.25% = 1025`) divided by 10,000.

## Run

From the repository root, on Node 20:

```bash
node --test tests/qa/oracle.test.js
```

No dependencies. The file uses `node:test` and `node:assert`.

## Seed

`20261001`

The generator is a mod-2^32 LCG (`state = 1664525 * state + 1013904223`). Orders, equal splits and by-item splits each restart from this seed. A failure message includes `seed=20261001` and the case index. The same line is printed at the start of every run.

## What is compared

`tests/qa/oracle.test.js` loads `js/calc.js` and calls only:

- `computeBill({ lines, billDiscount, orderType, settings })`
- `splitEqual(grandTotalSen, n)`
- `splitByItem(grandTotalSen, bases)`

If `js/calc.js` is missing, cannot be loaded, or does not export those three functions, the comparison tests are **skipped** with a message and the reference self-check still runs. That includes the R11 `RangeError` checks. A skip is not a pass of the implementation.

## Rules covered

- **R1** integer sen, including RM 0.10 + RM 0.20 (AC-21) and a large total (RM 123,456.78).
- **R2** subtotal is qty × unit price of non-voided lines. Empty orders and all-voided orders are 0 (AC-19, AC-33).
- **R3** bill-level percent (half-up) and RM discount, capped at the subtotal. AC-32 / W4 / MTS-07 (100% and an RM amount above the subtotal). AC-32a (10% of RM 12.35 → RM 1.24, base RM 11.11, and a fixed RM 5.00).
- **R4** service charge is Base × the order type's rate, only when that type is enabled. AC-22 (dine-in 10%, takeaway off), AC-23 (5%, off, takeaway 10% on), a 0% rate, and 10.25%.
- **R5** SST base is Base + rounded SC when "SST includes service charge" is on, otherwise Base. SST is 0 when SST is off or the rate is 0. AC-24 / MTS-01, AC-25 / MTS-02, AC-26 / MTS-11, AC-27 / W3 / MTS-03, AC-28 (8%).
- **R6** half-up to the sen for SC, SST and a percent discount. W2 (1.005 → 1.01) distinguishes this from banker's rounding. Half a sen rounds up; 0.4 sen stays down.
- **R7** pre-rounding total = Base + SC + SST.
- **R8** 5-sen rounding by the last sen digit, including the AC-29 / MTS-04 table, AC-30 (.00 and .05), and 1, 2 and 3 sen.
- **R9** grand total = pre-rounding + adjustment, and it stays ≥ 0.
- **AC-31** rounding off leaves the adjustment at 0 and the grand total equal to the pre-rounding total.
- **AC-20** the eight sen fields from the §3 return shape.
- **AC-34** equal split for N = 2..20 allocates the grand total and is not 5-sen rounded.
- **AC-35 / MTS-05** RM 100.00 / 3 = 33.34 / 33.33 / 33.33. The extra sen is on sub-bill 1.
- **A-16** RM 35.00 / 3 floors to 11.66 and the whole remainder 0.02 goes to sub-bill 1 (11.68 / 11.66 / 11.66), both as an equal split and as equal by-item bases.
- **W5 / AC-38** floors of 4080 × base_i / 3500 are 1165, 2331 and 582; remainder 2 sen goes to sub-bill 1 (11.67 / 23.31 / 5.82).
- **AC-36** a qty > 1 line is one base. The generator does not divide a line.
- **AC-37 / MTS-06** a voided line is not a split base.
- **AC-38** when the sum of bases is 0, every sub-bill is 0.00 (this is the one case where the parts are not required to sum to a nonzero grand total).

Invariants checked on every generated bill: non-negative amounts (the rounding line may be −2..+2), base = subtotal − discount, discount ≤ subtotal, pre-rounding = base + SC + SST, grand = pre-rounding + rounding, voided lines absent from the subtotal, SC 0 when that order type's SC is off, SST 0 when SST is off, and the R8 digit table when rounding is on.

Invariants checked on every generated split: parts ≥ 0, remainder sen sit entirely on sub-bill 1 (index 0), and the parts sum to the grand total. Equal splits cover every N from 2 to 20, including remainders larger than 1 sen so a one-sen spread would fail.

## Not generated

**Shared items.** AC-36 says each non-voided line goes whole to exactly one sub-bill, and a line with qty > 1 cannot be divided. By-item cases do not split a line across people.

The comparison suite asserts `assert.throws(fn, RangeError)` and no calculated amounts, for:

- `splitEqual` with `n` of 0, 1, 21, 2.5, -2, and NaN
- `splitByItem` with a negative base
- `computeBill` with a negative price, a negative quantity, a negative service-charge rate, and a negative RM discount, each built from an otherwise valid dine-in fixture

These checks skip with the other comparison tests when `js/calc.js` or the §3 exports are missing. They are not todos, and they are not weakened when the implementation does not throw yet.

## Readings fixed by a worked example

These are specified, and the oracle follows them:

- Percent discount is rounded, then subtracted. AC-32a is 12.35 − 1.24 = 11.11, not a rounded 90% of the base.
- SC is rounded before it enters the SST base (R5, W1).
- Equal-split remainder is floored, then the whole remainder is added to sub-bill 1. A-16's 0.02 all goes to the first share (11.68 / 11.66 / 11.66), not one sen each (11.67 / 11.67 / 11.66).
- `remainderSen` is that leftover, already included in `amounts[0]`.
- When the sum of by-item bases is 0, §3 says the return is all zero, so `remainderSen` is 0 as well.
